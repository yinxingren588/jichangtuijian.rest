比较两条节点配置时，先固定自己的设备、接入网络与目标任务，再交替测试，并保留所有失败。只有把条件写清楚，图上的数字才有解释范围。

## 适用范围

适用于你已经有权使用的两条配置，不需要为教程购买新服务。本站[图表资料库](/evidence/)可提供读图参考，但现有图片没有对应的本地运营商、设备及带宽记录，不能自动套入你的环境。

## 开始前准备

准备同一台设备、同一个接入网络、可信客户端和一个非敏感目标任务。先设置测试流量预算；大文件或测速服务可能消耗套餐额度，不必为了比较反复跑满带宽。保存未完成工作，不改证书校验或系统安全设置。

## 操作步骤

### 第1步：写下固定环境

记录日期、准确时间及时区、接入运营商、Wi-Fi或有线、带宽套餐、设备、系统和客户端版本。写不清的字段标为未知，不把设备网卡标称速率当作实际互联网带宽。

### 第2步：规定任务与判定标准

选择相同的网页、下载对象或应用任务，并预先规定尝试次数、观察时长和成功标准。延迟、下载、平台页面能否打开和账号能否完成任务应分别记录；一个指标正常不代表其余指标通过。

### 第3步：测试节点A

先确认未连接时普通网络正常，再按客户端受支持方式连接A。记录节点标识、开始时间、每次结果、错误提示和消耗额度。不能只保留最好的一次，也不把失败样本从分母中删除。

### 第4步：切换节点B并交换顺序

按正常流程切到B，保持设备、网络和目标尽量一致。记录切换时间与是否重新连接。条件允许时再按B、A的顺序观察，减少单一先后顺序造成的时间偏差；发生Wi-Fi切换或其他下载时注明。

### 第5步：按指标分别整理

使用原始单位保存下载结果：MB/s与Mbps不同，页面上的两类延迟也不要合并。平台状态如果只是页面访问结果，就只写访问结果；账号资格和内容地区另查。样本条件不同的地方一并说明，不强行得到一个综合分数。

### 第6步：结束测试并保留恢复结果

切回原本配置或正常断开，检查普通网页与实际工作应用是否恢复。记录退出后代理、路由或断网保护是否有遗留。原始记录留在个人存储中，对外分享时隐藏完整订阅、账号及支付信息。

| 记录字段 | 建议内容 |
|---|---|
| 环境 | 时间及时区、运营商、接入方式、设备及客户端版本 |
| 节点 | A或B、地区与脱敏标识，不含订阅令牌 |
| 任务 | 相同目标、次数、时长和成功标准 |
| 结果 | 每次成功或失败、错误、延迟或下载原始单位 |
| 干扰 | 同时下载、网络切换、客户端重连等变化 |
| 收尾 | 原配置恢复、普通网络与工作应用结果 |

## 完成后应该得到什么

你应能描述“A和B在这个时段、这套设备与接入网络下，对这个任务的观察差异”。这仍是有限样本；长期稳定性需要跨时段、持续记录失败及恢复，不从单次峰值推出全年表现。

## 无改善时怎样恢复

停止额外流量测试，恢复原配置，只检查本次确实改过的设置。如果两条配置都失败，先回到[基础连接排查](/guides/connection-check/)确认本地网络及配置有效状态，不批量重置适配器或同时更改DNS和代理。

## 何时停止继续操作

达到流量预算、普通网络异常、出现证书错误，或需要不明权限时停止。无法固定条件时，记录观察也有价值，但应明确条件变化，不标为严格的同环境结论。
