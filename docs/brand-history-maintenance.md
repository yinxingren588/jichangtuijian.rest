- 28份资料快照建立于2026-10-26，保留当时本站记录的56档套餐及12个优惠码，不宣称当日重新读取商家报价。

- 12条优惠确认记录沿用站长在2026-10-24的明确确认，只说明优惠价永久有效，不把它扩展为新增折扣、适用档位或结算核验。
- 本轮没有实际调价记录，也没有补造过去的价格变动。快照建立后发生的真实资料修订才追加到历史中。

## 后续更新流程

1. 根据新资料修改src/data/brand-catalogue.json，保留币种、实际付款周期、年付总额或月均、流量发放与倍率口径。只有重新读取来源后，才修改referenceChecked；不得用页面编辑日期代替。
2. 执行`npm run brand:record -- --brand 品牌slug --date YYYY-MM-DD --note "本次修改的依据和范围"`。日期与说明均由维护者明确填写。工具比较最新快照，只在资料实际变化时追加记录，不覆盖旧快照；同日多次修改按追加顺序保留，其他品牌不受影响。
3. 检查src/data/brand-buying-guides.json的适用需求、付款模型与判断是否仍成立。plan:0、plan:1、couponCode等事实占位符会同步当前字段，但“月付”“年付”等编辑判断不会凭空自动重写。套餐增减或顺序调整尤其需要人工审阅。其他固定编辑段落也应一并检查。
4. 有新的实际测速时，按原图、真实测试时间与已知环境补充。不要把已有图重复发布成新测试；当前记录没有补齐的运营商、带宽、设备和原始日志仍保留未知。
5. 更新品牌页面实际修改日期，再运行构建、全站检查和`npm run export:decisions`。最后更新静态部署包，站长自行上线。

构建时会对照最新历史快照与当前资料库。价格、币种、付款模型、额度、重置口径、优惠码或来源日期改变却没有追加记录时，构建会提示维护者补录。记录工具不会访问商家、核验优惠、计算券后价、更新外部账户或向搜索引擎提交URL。
